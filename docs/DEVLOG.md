## 产品定位

**核心定义**：一个私人的自我觉察空间，不是 AI 驱动的日记，而是以人为主、AI 适时辅助的记录与成长工具。

**用户画像**：有正念/觉察需求，曾有情感解离经历，希望通过日记重建对自身感受的连接，感性和理性都能运转。目前单用户，保留未来多用户可能。

**产品哲学（核心原则）**：
> 自己能识别自己觉察的 → 代码能做的代码做 → AI 只做人和代码都做不到的事

**AI 角色定位**（已确认）：
- 镜子（帮你看清自己说了什么）→ 向导（帮你发现更深的感受）→ 教练（只在被邀请时出现）
- AI 不凌驾于用户之上，不主动 push，适时出现
- 对于轻松愉悦的内容：不介入，直接保存

**一年后"有帮助"是什么样**：
- 所有碎片（情绪、灵感、学习、待办）都有地方放，不再散落各处
- 感知能力更强，直觉更敏锐，能相信自己的直觉
- 整个人更平静、更能知道自己当下需要什么
- 感性和理性齐头并进，自然而然地行动和休息

目标用户：想要了解自己内心、有自我成长需求的个人用户（目前单用户）

- 多模板写日记（感恩/学习/情绪/行动/随手记）

- user_profile：用户画像（跨对话积累）
- 存 Supabase，多端同步

## 关键设计决策记录

### 问题库设计（2024）
**决策**：AI 不自行生成问题，从预设问题库中选择
**原因**：质量更稳定，风格可控，Token 消耗更少
**影响**：问题库在 prompts.js 硬编码，改问题需要 git push

### AI 记忆存储位置（2024）
**决策**：存 Supabase（而非 IndexedDB）
**原因**：用户要求多端同步（换浏览器/换设备/清缓存都在）
**影响**：localDB.js 成为孤儿文件，待删除

### 提取流程去审阅（2024）
**决策**：点"完成"后静默提取，不展示审阅页
**原因**：减少强制节点，让流程更自然
**待讨论**：提取失败或提取有误时用户无感知，是否需要轻量反馈？

### 对话缓存机制（2024）
**决策**：localStorage 存对话（key: chat_session_{entry.id}）
**原因**：防止刷新丢失，轻量，不需要额外 DB 写入
**影响**：恢复对话时用的是旧 systemPrompt，prompts 更新不会立即生效

## 待讨论 / 搁置功能

### 整体产品信息流（已确认框架）
```
【输入层】文字 / 语音 / 快速记录 + 时间日期 + 人物@标注
    ↓ 立即保存（不等处理）
【并行处理层】
  本地检测（零token）：复杂度评分 / 时间识别 / 人物识别 / 基础标签
  AI轻量提取（可选）：primary_emotion / event_summary
【触发判断】复杂/负面 → 小字提示"要聊聊吗？" | 平静/愉悦 → 直接保存
    ↓（用户主动点击才触发）
【AI对话层】镜子 → 向导 → 教练（被邀请才出现）
    ↓
【记忆层】rolling_summary + user_profile → Supabase
    ↓（未来）
【分析层】情绪趋势图 / 语义搜索 / AI综合洞见
```

### AI 触发机制（已确认）
**复杂度评分逻辑**（纯本地，零 token）：
- 强负面情绪词（焦虑/难受/崩溃/委屈/绝望等）+2分/个
- 复杂/矛盾信号词（但是/纠结/说不清/不知道为什么等）+1分/个
- 内容超过150字 +1分
- 正面词（开心/幸福/舒服/感恩等）-1分/个
- 得分 ≥ 2 → 显示提示小字（固定文案，后续可按内容动态调整）
- 情绪词库可随时扩充，不影响其他代码

**分层实现原则**（可随时升级，零影响）：
- 第一版：关键词词库（当前）
- 升级版：浏览器内 ML 小模型（Transformers.js，本地运行）
- 终极版：结合 AI 提升准确率
- 封装为 `analyzeContent(text)` 函数，调用方不感知内部实现

### 智能标注系统（待实现，已确认设计方向）

**时间识别**（代码实现，零 token）：
- 今天 → 当前日期
- 昨天/前天 → 当前日期 -1/-2天
- 上周/上个月/去年 → 忽略，让用户手动选
- 早上 → 09:00 | 下午 → 16:00 | 晚上 → 21:00 | 凌晨 → 00:00
- 页面内嵌日期时间选择器，默认当前时间，可手动改

**人物识别**（代码实现为主，零 token）：
- 维护用户"人物库"：每人有主称呼 + 别名列表
  - 妈妈（别名：妈、母亲、老妈）
  - 男朋友（别名：男友、对象、bf）
  - 前任（别名：[用户自定义]、具体名字）
- 自动识别文本中的人物词 → 显示标签【@妈妈】
- 同时支持 @ 触发手动选择下拉列表
- 识别错误可点叉删除或点标签替换
- 人物库在设置页可管理（增删改别名）

**情绪标签**（手动为主，AI 最后才介入）：
- 记录情绪类型日记后，跳转情绪选择页
- 预设情绪按钮，按正面/负面/中性分组
- 可自定义增删排序，新增情绪自动归类（代码先匹配，匹配不到才 AI 判断）
- 找不到合适的 → "暂时无法明确定义这个感受" → 触发 AI 对话引导识别

**状态评分**：
- 内嵌评分条，-3 到 +3，7个选项（不用 10 个，太多）
- 嵌入在内容输入框下方，轻量，随手点选

**输入流程顺序**（心理学依据）：
1. 写内容（自由表达，先把大脑输出）
2. 选情绪标签（命名感受，本身就是觉察练习）
3. 整体状态评分 -3~+3（元认知，评估整体）
4. 处理方式评分（可选，有深入对话的才填）
- 基于 ACT / 正念原则：先体验，再命名，再评估
- 情绪标签 + 状态评分放同一页，不单独跳转
