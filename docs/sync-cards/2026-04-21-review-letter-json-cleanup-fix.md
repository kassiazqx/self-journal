# 同步卡：回顾信正文 JSON 残留修复（格式兼容增强）

**状态：** ✅ 已完成  
**日期：** 2026-04-21  
**commit：** 8560273

---

## 问题

回顾信正文末尾残留 JSON 代码（`[{"action":"create",...}]` 后跟 ` ``` `），未被清理掉。

## 根本原因

AI 实际输出格式为：

```
[信的正文]
[
  {"action": "create", "thread_name": "...", ...}
]
```
（结尾是三个反引号 ` ``` `，单独一行）

原清理正则 `\[[\s\S]*"thread_name"[\s\S]*\]\s*$` 要求 `]` 之后只能有空白字符（`\s*$`），但 `]` 后面跟着 ` ``` `，导致匹配失败，三种格式全部不命中，rawLetter 原样存入数据库。

## 修复

三条 replace 均改为**删至字符串末尾**（`[\s\S]*$`），不再依赖 `]` 在末尾的位置：

```js
// 修复前
.replace(/\[[\s\S]*"thread_name"[\s\S]*\]\s*$/, '')  // ] 必须在末尾，有杂质就失配

// 修复后  
.replace(/\[[\s\S]*"thread_name"[\s\S]*$/, '')        // 从 [ 删到字符串末尾，无论后面跟什么
```

同时新增格式A2（无 `json` 标签的代码块），并将 console.warn 改为输出末尾500字，便于复现未知格式。

## 架构影响

无。仅 `reviewLetterService.js` 内部正则调整。

## 预防建议（见 arch-context §4.41）

AI 输出格式不可完全预测，任何 AI 输出解析代码必须：
1. 将日志从"前500字"改为"末尾500字"（JSON 在末尾，前500字是正文）
2. 清理正则不依赖末尾锚点，改为"从特征词删到末尾"
3. 每次发现新格式后立即扩展 pattern，不假设 AI 只会输出固定格式
