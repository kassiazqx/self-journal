识别规则（取最近且不超过当前时刻）：
  • 「昨天/昨晚/昨夜」→ 昨天（+时段）
  • 「前天」→ 前天
  • 「大前天」→ 三天前
  • 「现在/刚刚」→ new Date()
  • 「早上/上午」→ 今天 09:00
  • 「中午」→ 今天 12:00
  • 「下午」→ 今天 16:00
  • 「傍晚」→ 今天 18:00
  • 「晚上/夜里」→ 今天 21:00
  • 「凌晨」→ 今天 01:00
多个关键词同时出现：过滤未来时间点，取最近的。

方案 B · 日期在引导词行右侧
缺点：引导词行已有竖线+文字，再加日期显得拥挤；
且引导词行各模板不一样长，日期位置不稳定。

→ 推荐方案 A，模板栏右侧空间天然富余。
自动识别规则（复用旧版 inferDatetime 逻辑）
关键词 日期偏移 时间 优先级
今天±0不变最低（默认）
昨天 / 昨晚 / 昨夜-1昨晚→21:00，其余不变中
前天-2不变中
大前天-3不变中
早上 / 上午 / 今早 / 今晨±009:00低
中午±012:00低
下午±016:00低
傍晚±018:00低
晚上 / 夜里 / 今晚±021:00低
凌晨±001:00低
· 日期和时段关键词可叠加：「昨晚」= 昨天 + 21:00
· 同一类重复出现取最强偏移（「昨天前天」→ 前天，即 -2）
· 识别触发时机：每次输入停顿 800ms 后 debounce 检测
· 识别只影响当前写作会话的 selectedDatetime state，不直接写 DB
· 用户手动修改过日期后，自动识别不再覆盖（手动优先）
数据流
1. mount 时：selectedDatetime = new Date()（当前时间）
2. 用户输入触发 inferDatetime() → 有匹配关键词时更新 selectedDatetime
3. pill 展示 selectedDatetime，与「今天当前时间」不同时变金色
4. 用户点 pill → 打开 sheet → 手动调整 → 确认 → 更新 selectedDatetime
5. 点 ✓ 保存：created_at = selectedDatetime.toISOString()
⚠️ 编辑模式（editEntry）：selectedDatetime 初始值 = editEntry.created_at
