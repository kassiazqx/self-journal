# 输入流程重设计 · 设计文档

**日期**：2026-04-06  
**状态**：已确认，待实现

---

## 背景与目标

当前写日记的流程是"选模板 → 写内容 → 进 AI 对话"，缺少情绪标签、状态评分、人物标注等结构化入口。本次重设计目标：

1. 加入两页输入流程（Page 1 写内容 → Page 2 标注情绪）
2. 所有记录事后可编辑（原文 + 所有标签）
3. 修复移动端删除交互冲突
4. 为 AI 复杂度触发提供数据基础

---

## 模板结构（5个）

| 模板名 | Emoji | 说明 |
|---|---|---|
| 感恩・美好 | 💛 | 记录每天感恩的小事、被感动的瞬间 |
| 情绪觉察 | 😤 | 有情绪卷入、需要探索 |
| 念头・灵感 | ✨ | 一闪而过的念头、不一定需要深度处理 |
| 学习输出 | 🧠 | 知识/洞见的沉淀 |
| 行动记录 | 🏃 | 运动、执行、完成了一件事 |

**重要**：模板 = 入口体验，不是永久约束。底层所有记录共用同一张 `journal_entries` 表，字段完全相同。模板只影响写入时的引导和 Page 2 的必填程度。记录完成后，template_type 字段仅作为显示标签。

---

## 整体流程

```
HomePage（写内容 Page 1）
  → 点【下一步】→ 内容立即保存到 Supabase
                → 本地跑复杂度评分（暂存结果）
  → TaggingPage（标注 Page 2）
  → 点【完成】  → 情绪标签 + 状态评分 + 处理复盘 UPDATE 写回记录
                → 复杂度评分 ≥ 2 → 显示"好像有点复杂，要聊聊吗？"
                → 否则回记录列表
```

## Page 1：写内容（改动 HomePage）

**布局**（从上到下）：
1. **模板选择**：保持现有样式（1-2行全展示，不横向滚动）
2. **内容输入框**：自适应高度，自动识别后直接显示 `@人物` 标签（不加"自动检测到："前缀）
3. **日期时间选择**：默认当前时间，点击可展开修改
4. **下一步按钮**：右下角，点击立即保存并跳转 Page 2

**"下一步"时发生的事**（静默）：
- 保存内容、模板类型、时间到 Supabase
- 本地运行 `analyzeContent(text)` 复杂度评分，暂存结果（不立即触发任何 UI）

## Page 2：情绪标注（新增 TaggingPage）

**布局**（从上到下）：
1. **顶栏**：返回箭头 + 标题"情绪标注"
2. **情绪标签**：按组展示，多选，不同模板显示不同必填要求
3. **状态评分条**：-3 到 +3，7个节点
4. **处理方式复盘（可展开卡片）**：所有模板都有，默认折叠

**各模板的必填程度**：

| 模板 | 情绪标签 | 状态评分 | 处理复盘卡片 |
|---|---|---|---|
| 情绪觉察 | 必选（≥1个） | 必填 | 可展开 |
| 感恩・美好 | 必选（仅正面词库） | 必填 | 可展开 |
| 念头・灵感 | 可跳过 | 可跳过 | 可展开 |
| 学习输出 | 可跳过 | 可跳过 | 可展开 |
| 行动记录 | 可跳过 | 可跳过 | 可展开 |

**情绪标签分组**：
- 正面：开心 / 感激 / 平静 / 温暖 / 满足 / 喜悦 / 被爱 / 自豪 / 轻松 / 兴奋
- 负面：焦虑 / 委屈 / 失落 / 难受 / 愤怒 / 孤独 / 崩溃 / 压抑 / 绝望 / 内疚
- 中性：困惑 / 思考 / 平淡 / 麻木 / 矛盾 / 期待 / 好奇 / 疲惫

**处理方式复盘卡片（展开内容）**：
- 处理评分（从以下选一：处理得很好 / 还不错 / 勉强应对 / 处理失当 / 失控了）
- 简短反思输入框（可选文字）

**"完成"时**：
- 将情绪标签 / 状态评分 / 处理复盘 UPDATE 到 Supabase 同一条记录
- 检查暂存的复杂度评分 → ≥ 2 显示"好像有点复杂，要聊聊吗？"
- 否则回记录列表

## 编辑功能（修改 RecordsPage + RecordDetail）

**触发方式（两个入口）**：
1. **记录列表**：长按某条记录 → 下拉菜单（编辑 / 删除）
2. **记录详情页**：右上角"…"按钮 → 展开菜单（编辑 / 删除）

**编辑界面**（合并为单页）：
- 原文输入框（可修改内容）
- 情绪标签（显示已选，可重选）
- 状态评分条（可修改）
- 处理方式复盘卡片（可展开修改）
- 顶栏：取消 | 保存

**同时删除**：桌面鼠标悬浮显示删除图标的交互——移动端无效且与点击进详情冲突，直接移除。

## 复杂度评分逻辑（新增 lib/contentAnalysis.js）

```javascript
// 封装为独立模块，调用方不感知内部实现
export function analyzeContent(text) → { score, shouldSuggestChat }

// 评分规则（纯本地关键词，零 token）
强负面词（焦虑/难受/崩溃/委屈/绝望等）：各 +2
复杂/矛盾信号词（但是/纠结/说不清/不知道为什么等）：各 +1
内容超过150字：+1
正面词（开心/幸福/舒服/感恩等）：各 -1
score ≥ 2 → shouldSuggestChat: true
```

**升级路径**（不影响调用方）：
- 第一版：关键词词库（当前）
- 升级版：浏览器内 ML 小模型（Transformers.js）
- 终极版：结合 AI

## 成功标准

1. 写完日记点"下一步"，内容立即保存，Page 2 正常展示
2. 情绪标签可多选，状态评分可点选
3. 点"完成"后，情绪字段正确写入 Supabase 对应记录
4. 复杂度高的内容（手动测试：包含"焦虑"或"但是"+"不知道"）完成后显示"聊聊吗？"提示
5. 长按列表记录出现编辑/删除菜单
6. 详情页"…"出现编辑/删除菜单
7. 编辑保存后，记录内容和标签正确更新
8. 移动端无鼠标悬浮删除图标干扰
9. npm run build 零报错
