# 回顾信 Prompt 重设计

**日期：** 2026-04-21  
**状态：** ✅ 设计确认

---

## 一、目标

将当前单一固定 prompt 替换为三种格式（A/B/C），由 AI 在一次调用中完成「选格式 + 写信 + 输出 suggested_threads」。同时引入时间感知问候，由代码注入时段词、AI 写观察后半句。

---

## 二、核心架构决策

| 决策 | 结论 | 理由 |
|---|---|---|
| 格式选择由谁做 | **AI**（单次调用内） | 代码规则是代理指标，AI 读全文判断更准；未来加格式 D 只改 prompt，代码不动 |
| API 调用次数 | **不变**（仍一次） | AI 在同一次调用里选格式、写信、输出 JSON；无额外成本 |
| 格式 C 时机 | **暂缓** | 行为模式判断依赖原文，当前只传摘要，条件不成熟 |
| 入参字段 | `entry_summary + theme_hints + core_needs`（不加原始 `content`） | 原文 token 消耗大；AI 从摘要挑句子够用；格式 A 靠结构化字段判断 |
| `suggested_threads` | **不变** | 随信一起输出，解析逻辑不动 |

## 三、模板变量

| 变量 | 来源 | 说明 |
|---|---|---|
| `{{time_greeting}}` | **代码生成**（见 §六） | 时段词，如「晚上好」「早啊」 |
| `{{entry_count}}` | 代码：`entries.length` | 本次纳入条目数 |
| `{{date_range}}` | 代码：最早/最晚 `created_at` | 格式：`YYYY/MM/DD—YYYY/MM/DD` |
| `{{entries_with_dates_and_content}}` | 代码：每条拼接（见 §四） | 一条一行 |

### `{{entries_with_dates_and_content}}` 格式

每条条目拼为一行：

```
[YYYY/MM/DD] 摘要：{entry_summary} | 主题：{theme_hints} | 核心需求：{core_needs}
```

`theme_hints` / `core_needs` 若为空则省略对应 `| 主题：` / `| 核心需求：` 片段。

---

## 四、格式选择规则（写入 system prompt，AI 执行）

**步骤：** AI 先读完所有条目，再按以下规则选格式，然后按该格式写信。

### 格式 A 触发条件（满足任一）

- `theme_hints` 或 `core_needs` 中，同一个词出现在**超过一半**的条目中（严格 >50%，即出现次数 > 总条目数 × 0.5）
- 同一个词出现在 **≥ 5 条**条目中

优先统计 `theme_hints` / `core_needs` 字段（结构化，便于计数）；若这两个字段稀疏，可同样统计摘要文字中的词频来判断。

### 格式 B（默认）

不满足格式 A 条件时使用。

### 格式 C（暂缓）

当前不启用，system prompt 中不描述，等后续条件成熟再加。

## 五、三种格式写作规范

### 格式 A：一根线

**核心动作：** 找到贯穿这段时间的一个词、一种感受、或一个反复出现的意象，用原文（摘要）里的具体句子把它照出来。

**结构：**
1. `{{time_greeting}}` + AI 写的观察后半句（一句话，不超过 20 字，点出那条线）
2. 正文：从各条目里摘出 2–6 个包含这个词/感受的句子，每句前标日期，不加解释、不加标题
3. 不做总结，不给建议，信到此结束

**禁止：** 分析、解释、"这说明你……"、结尾总结段

**示例结构：**
```
{{time_greeting}}，这阵子好像一直在等什么。

4月3日，你说……
4月7日，你写……
4月12日，你提到……
```

---

### 格式 B：关键时刻

**核心动作：** 从这段时间的条目里，找 2–6 个最有力量、最真实的时刻或原句，原样呈现，不加任何评论。

**结构：**
1. `{{time_greeting}}` + AI 写的观察后半句（一句话，不超过 20 字，给出这段时间的整体感）
2. 正文：2–6 个时刻，每个前标日期，一两行，引用摘要中最有力的表达
3. 信到此结束

**禁止：** 分析、连接词"因为""所以"、结尾总结

**示例结构：**
```
{{time_greeting}}，这段时间有些时刻特别清晰。

4月5日
你说……
4月11日
你写……
```

---

### 格式 C：模式照见（暂缓）

**暂不实现。** 需要原始文字才能判断行为/关系模式，当前入参只有摘要，等后续再加。

## 六、时间问候系统

### 时段划分与词库

| 时段（本地时间） | 可选词（代码随机取一） |
|---|---|
| 05:00–10:59 | 早上好 / 早啊 / 早 |
| 11:00–13:59 | 中午好 / 午安 |
| 14:00–17:59 | 下午好 |
| 18:00–22:59 | 晚上好 / 晚啊 |
| 23:00–04:59 | 还没睡呢 / 深夜了 |

### 职责分工

- **代码**：根据本地时间选取 `time_greeting` 词，注入 `{{time_greeting}}`
- **AI**：接收 `{{time_greeting}}`，写问候的后半句观察（一句话），构成完整开头

AI 写的后半句要求：
- 不超过 20 字
- 是对这段时间状态的一个轻盈观察，不是总结
- 不重复 `time_greeting` 的词
- 整行读起来自然，像一个人对另一个人说话

---

## 七、suggested_threads 输出块

**不变。** 三种格式信的正文结束后，均附上现有的 `suggested_threads` JSON 指令和输出结构，解析逻辑不改。

## 九、成功标准

1. 同批条目中有贯穿性词汇时，AI 选格式 A，信里有对应词的多条摘引
2. 无贯穿性词汇时，AI 选格式 B，信里有 2–6 个有力时刻
3. 信的开头是 `{{time_greeting}}` + AI 观察，符合时段
4. 深夜打开时开头词为「还没睡呢」或「深夜了」之一
5. 信的正文后依然有 `suggested_threads` JSON，解析正常
6. 格式 A 的信里没有分析解释段，格式 B 的信里没有连接词/总结
