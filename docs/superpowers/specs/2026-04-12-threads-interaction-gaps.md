## §A 脉络关联记录的手动增删

### A.1 入口

脉络详情页右上角「···」浮窗菜单 → 「📝 编辑关联记录」→ 进入编辑模式。

「···」菜单为**右对齐小浮窗**（宽约 154px），与脉络详情页顶部右侧「···」按钮对齐，包含以下选项：

| 选项 | 颜色 | 操作 |
|---|---|---|
| ✏️ 编辑名称 | 正常 | 内联编辑或弹出输入框 |
| 📝 编辑关联记录 | 正常 | 进入编辑模式（见 A.2） |
| 🔄 重新分析 | 正常 | 见 A.4 |
| 📁 归档 | 橙色警示 | 见 §C |
| 🗑️ 删除 | 红色危险 | 二次确认后永久删除 |

### A.2 编辑模式 UI

进入编辑模式后：
- 页面顶部出现**橙色 banner**「编辑关联记录 ……… 完成」，说明当前在编辑模式
- **搜索框固定在 banner 下方**（顶部），用于搜索并添加记录
- 现有关联记录列表显示在下方，每条右侧有**红色 × 按钮**用于移除
- 搜索框有内容时，下方显示搜索结果列表，每条左侧有**绿色 + 按钮**用于添加
- 点「完成」保存并退出编辑模式

### A.3 增删规则

**删除（移除）规则：**
- AI 关联的记录（`added_by='ai'`）和用户手动加入的记录（`added_by='user'`）**均可被用户手动移除**
- 移除时在 `thread_entries` 表新增字段 `removed_by_user = true`，**不物理删除行**
- 被标记 `removed_by_user=true` 的记录：AI 后续「重新分析」此脉络时**不会重新关联**（用户排除决定被尊重）

**添加规则：**
- 用户手动添加时，`added_by='user'`，`removed_by_user=false`
- 手动添加的记录 AI 无法自动移除

### A.4 重新分析（单条脉络）

入口：「···」菜单 → 「🔄 重新分析」

**分析范围**：只扫描**从未被此脉络评估过**的新 entry（不在 thread_entries 表中，包括未被排除的）。已被 `removed_by_user=true` 标记的记录跳过。

**上下文带入**：AI 调用时必须带入当前脉络的**名称 + arc_summary**，让 AI 知道「这条脉络是关于什么的」，才能正确判断新 entry 是否相关。不带上下文会导致 AI 发现与原脉络无关的模式。

**结果处理**：新发现的相关 entry 写入 `thread_entries`（`added_by='ai'`），状态默认为待用户确认（可在脉络详情页看到提示），不自动加入。

### A.5 arc_summary 更新时机

**不自动更新**。当用户手动增删关联记录后，arc_summary 进入过期状态：

- 脉络详情页顶部轨迹区显示**黄色警告**：「⚠ 关联记录已更改，AI 轨迹摘要尚未更新」
- 附带可点击链接「点击重新生成轨迹 ›」
- 用户不点击也没问题，旧轨迹保留，只是可能不准确
- 点击后异步调用 AI 生成新的 arc_summary，生成完成后覆盖写入

## §B 候选脉络的确认流程

### B.1 三种候选状态

候选脉络（`status='candidate'`）有三种结果：

| 操作 | 结果 | 数据库 | AI 下次会重复提议吗 |
|---|---|---|---|
| 接受 | 转为已确认脉络 | `status='confirmed'` | — |
| 忽略 | 变灰，保留在待确认列表下方 | `status='rejected'` | ❌ 不会（有记录可过滤） |
| 删除 | 彻底清除 | 行被删除 | ✅ 可能会（失去记录） |

### B.2 「直接返回」处理

用户进入候选详情页后**未做任何操作直接返回**：候选保持原 `status='candidate'`，待确认列表保持不变。等同于「看了但还没决定」，无需特殊处理。

### B.3 待确认 Tab 列表布局

```
待确认 Tab 内容结构：
┌─ 活跃候选（status='candidate'）─────┐
│  正常色卡片，点入看详情              │
│  来源标签：回顾信触发 / 手动分析     │
├─ 分隔线 + 「已忽略」小标题 ──────────┤
│  灰色卡片（status='rejected'）       │
│  右侧有「删除」按钮                  │
└──────────────────────────────────────┘
```

- 活跃候选卡片：点击 → 候选详情页
- 灰色忽略卡片：**不可点击进详情**，仅展示名称/来源/条数，右侧「删除」按钮触发永久清除
- 待确认 Tab 角标数量只计算活跃候选（`status='candidate'`），不计已忽略

### B.4 候选详情页

页面展示：
1. 脉络名称 + 来源标签（回顾信触发 · 日期 / 手动分析 · 日期）
2. AI 发现理由（一段文字说明）
3. 关联记录列表（只读，可点击跳转到笔记详情）
4. 底部操作按钮：`[ ✓ 接受这条脉络 ]  [ 忽略 ]`

点「接受」→ `status='confirmed'`，跳回已确认 Tab，顶部显示绿色成功 toast（约 3 秒自动消失）。
点「忽略」→ `status='rejected'`，返回列表，该候选出现在灰色区域。

### B.5 候选 Tab 角标

待确认角标（橙色数字）仅统计 `status='candidate'` 的数量，已忽略（`status='rejected'`）不计入，避免角标虚高。

## §C 脉络归档与删除

### C.1 归档入口

已确认脉络详情页「···」菜单 → 「📁 归档」→ 弹出二次确认弹窗 → 确认后 `status='archived'`。

### C.2 已归档 Tab

- ThreadsPage 第三个 Tab，标题「已归档」
- 卡片降低透明度（opacity ≈ 0.7），显示归档日期
- 点击 → 归档态脉络详情页

### C.3 归档态详情页

- **完全只读**，顶部有「已归档」灰色角标，无「···」菜单
- 顶部有只读 banner「已归档 · 归档于 X月X日 · 仅供查看」
- arc_summary 和关联记录可浏览（点击记录可跳到笔记详情）
- 底部固定操作栏：`[ ↩ 恢复为活跃脉络 ]  [ 永久删除 ]`

### C.4 永久删除

点「永久删除」→ 居中确认弹窗，说明：
- 「脉络及其 N 条关联关系将被永久删除」
- 「原始笔记不受影响」
- 「操作不可撤销」
- 按钮：`[ 取消 ]  [ 确认删除 ]`（确认为红色）

删除操作：`DELETE FROM threads WHERE id = ?`（`thread_entries` 因外键 CASCADE 自动清除）。原始 `journal_entries` 记录完整保留。

### C.5 渐进路径

```
已确认 → 归档（···菜单）→ 永久删除（归档态底部）
已确认 → 直接永久删除（···菜单，需二次确认）
```

两条路径都可，「归档」是软过渡，给用户反悔空间。

## §D 手动触发脉络分析的 UI 流程

### D.1 入口

两个等价入口：

1. **ThreadsPage 已确认 Tab 底部**：虚线样式「🔍 AI 分析发现新脉络」按钮
2. **ThreadsPage 右上角「+」浮窗** → 选「🔍 AI 分析发现」

「+」为右对齐小浮窗（宽约 154px），两个选项：
- ✏️ 手动创建（命名 + 手动选 entry）
- 🔍 AI 分析发现（进入下方确认 sheet）

### D.2 确认 sheet

点任意 AI 分析入口后，从底部弹出确认 sheet，内容：

- 标题：「AI 分析脉络」
- 副标题：「选择分析范围，AI 会在这段时间的记录里寻找规律」
- 提示框（橙色）：「⏱ 通常需要 10~20 秒，分析期间可继续使用 App」+ 「📋 结果以候选形式出现，需逐一查看后确认」
- 时间范围选择（横向滑动 chip）：`7天 / 30天 / 半年（默认） / 1年 / 全部`
- 按钮：`[ 取消 ]  [ 开始分析 ]`

### D.3 分析中状态

点「开始分析」后：
- 入口按钮变为 loading 状态（spinner + 「正在分析…」文字）
- 页面其余部分仍可正常滚动使用
- 分析在后台进行，不阻塞 UI

### D.4 分析完成

分析完成后：
- 入口按钮恢复正常，副文字更新为「上次：刚刚」
- 底部出现 toast：「发现 N 个脉络候选，已加入待确认」+ 「去查看 ›」按钮
- 点「去查看 ›」跳转到 ThreadsPage 待确认 Tab
- 若无新候选：toast 显示「暂时没有发现新脉络，稍后再试」

### D.5 分析范围说明

方式 B（手动分析）的候选召回策略与主 spec §4.2 相同，使用本地评分粗召回 + AI 精筛，只是时间范围由用户选定。

## §E category_tags 编辑

### E.1 字段说明

`journal_entries.category_tags`：内容大类标签，JSON array，如 `["#人际", "#情绪"]`。由 AI 在对话提取时自动填入，用户可事后编辑。

### E.2 展示位置

笔记详情页（RecordDetail）顶部信息卡（`d-header-card`）内，位于 state chip 下方，单独一行。

显示：`#人际` `#情绪` 等小 chip，末尾有 `✎` 图标触发编辑。

### E.3 编辑交互

点击 category chips 区域（或末尾 `✎`）→ **从底部弹出 sheet**：

- 标题：「选择内容大类标签」
- 内容：预设标签 chip 网格（多选，已选高亮橙色）
- 底部说明：「在「我的」页面可以自定义这些标签」
- 按钮：`[ 取消 ]  [ 保存 ]`

点「保存」→ 写回 `journal_entries.category_tags`（array）。点「取消」→ 关闭不保存。

### E.4 标签数据来源

预设标签从 `user_options` 表读取，与其他自定义选项统一管理。默认预设（可在「我的」页面增删）：`#人际 / #情绪 / #工作 / #身体 / #家庭 / #自我成长 / #金钱 / #日常`。

## §H 「我的」页面：内容大类标签管理

### H.1 入口

「我的」页面 → 「自定义选项」分组 → 「内容大类标签」行（显示当前标签数量）→ 进入标签管理页。

### H.2 标签管理页 UI

- 标题：「内容大类标签」
- 列表：每条显示 ☰ 拖动手柄 + 标签 chip 预览 + − 删除按钮
- 列表底部：「+ 添加新标签」绿色按钮行
- 列表下方：说明文字「删除标签不影响已打过该标签的笔记记录」

### H.3 操作说明

**排序**：长按 ☰ 拖动调整顺序。排序结果同步到 user_options 表（可用 sort_order 字段），编辑面板里的 chip 排列顺序随之更新。

**删除**：点 − 按钮直接删除（无需二次确认，误删可手动重新添加）。
- 只从 `user_options` 删除该选项
- **已打过该标签的笔记 `category_tags` 字段不受影响**（历史数据保留）
- 删除后该标签不再出现在编辑面板的选项里

**新增**：点「添加新标签」→ 列表底部出现内联输入框（不跳转新页）。输入标签名（建议加 # 前缀，不强制），点「完成」保存到 `user_options`。

### H.4 数据结构

```sql
-- user_options 表（已有），内容大类标签的 category 字段值为 'content_category'
-- sort_order 字段需新增（当前表中不存在）
ALTER TABLE user_options ADD COLUMN sort_order integer NOT NULL DEFAULT 0;

SELECT * FROM user_options
WHERE user_id = ? AND category = 'content_category'
ORDER BY sort_order ASC;
```

## §F 数据库变更补充

### F.1 thread_entries 新增字段

```sql
ALTER TABLE thread_entries
  ADD COLUMN removed_by_user boolean NOT NULL DEFAULT false;
```

用途：标记用户手动移除的关联，防止 AI 重新分析时再次添加。

### F.2 threads 状态值扩展

原 spec §2.2 中 threads.status 的 CHECK 约束需更新：

```sql
-- 原约束：
CHECK (status IN ('candidate','confirmed','archived'))

-- 更新后（新增 rejected）：
CHECK (status IN ('candidate','confirmed','archived','rejected'))
```

`rejected`：候选被用户忽略，保留记录供 AI 过滤，不展示为活跃候选。

### F.3 原状态机更新

```
candidate  →  接受 → confirmed
candidate  →  忽略 → rejected（灰色保留，AI 不重复提议）
candidate  →  删除 → 行删除（AI 可能重复提议）
confirmed  →  归档 → archived
confirmed  →  删除 → 行删除（二次确认）
archived   →  恢复 → confirmed
archived   →  永久删除 → 行删除（二次确认）
rejected   →  删除 → 行删除（灰色卡片右侧触发）
```

## §G 洞察页脉络区块的候选提示

当方式 A（随回顾信）发现新候选时，洞察页脉络区块显示提示：

**区块 header 右侧**：橙色角标「N 个待确认」（badge）+ 原有「查看全部 ›」链接并排。

**区块底部**：橙色提示条「回顾信生成时发现了 N 个新脉络候选 · 去确认 ›」，点「去确认」直跳 ThreadsPage 待确认 Tab。

无候选时：提示条不渲染，区块 header 只显示「查看全部 ›」。

## §I RecordDetail 顶部标签区交互重设计

> 本节是对主 spec（`2026-04-11-threads-insights-design.md`）中 RecordDetail 展示设计的补充，覆盖四个可编辑字段的具体交互方式。

### I.1 设计原则

顶部标签区域的所有字段均支持**点击直接编辑**，无需进入专门编辑页面。三种交互模式：

| 字段 | 交互方式 |
|---|---|
| `template_type` | 点击 badge → 下拉框（单选，5 选项） |
| `emotion_display` | 点击任意 chip → 所有 chips 变为单个文字输入框 |
| `state_score` | 点击 chip → 下拉框（单选，7 选项，-3 to +3） |
| `category_tags` | 点击 chips / ✎ → 底部 sheet（chip 网格多选） |

### I.2 顶部标签区布局顺序

```
[ 觉察 ▾ ]                        ← template_type badge
[ 烦躁 ] [ 克制后的疲惫 ]          ← emotion_display chips（可点击编辑）
[ 状态 −1 ▾ ]                      ← state_score chip（emotion 后面）
[ #人际 ] [ #情绪 ] ✎              ← category_tags（最后一行）
```

### I.2 template_type 点击切换

展示：顶部信息卡左上角小 badge（如「觉察 ▾」），带向下小箭头暗示可点击。

点击后：弹出小下拉框（约 140px 宽），选项列表：
- 觉察（感受/情绪觉察）
- 感恩
- 学习
- 行动
- 随手记

点击某项 → 立即更新 `journal_entries.template_type`，badge 文字同步刷新，下拉框关闭。

### I.3 emotion_display 内联编辑

展示：若干 `emotion_display` chip（如「烦躁」「克制后的疲惫」），点击任意 chip 进入编辑模式。

编辑模式：
- 所有 chips 消失，变为**单个文字输入框**
- 输入框预填当前所有 emotion_display 词，以**顿号（、）**拼接（如「烦躁、克制后的疲惫」）
- 用户直接修改文字，支持增删改
- 输入框右侧有「✓」确认按钮，点击保存；按 Esc / 点外部取消

保存逻辑：
- 按「、」拆分字符串 → 得到新的 `emotion_display` 数组
- 同时调用 `mapDisplayToBase()` 映射 → 更新 `emotions` 数组（后端 base words）
- 两个字段同步写回 Supabase

> ℹ️ 现有代码（RecordDetail.jsx）已实现 `editingEmotions` 状态和 `mapDisplayToBase()` 函数，此设计与现有逻辑对齐，无需大改。

### I.4 state_score 下拉选择

展示：「状态 -1」样式的 chip，带向下小箭头。

点击后：弹出小下拉框（约 160px 宽），7 个选项：

| 选项 | 颜色 |
|---|---|
| +3 非常好 | 深绿 |
| +2 比较好 | 绿 |
| +1 还不错 | 浅绿 |
| 0 中性 | 灰 |
| −1 有点难 | 浅红 |
| −2 比较难 | 红 |
| −3 非常难 | 深红 |

当前值左侧显示 ✓。点击某项 → 更新 `journal_entries.overall_state_score`，chip 文字和颜色同步刷新。

### I.5 core_needs 确认保持现状

`core_needs`（核心需求）**已在主体字段区**（核心字段区 `EditableFieldRow`），无需移动。不放入顶部标签区。
